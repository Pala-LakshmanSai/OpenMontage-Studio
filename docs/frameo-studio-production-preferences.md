## Start and refill useful work

AI Movie and Queen Elizabeth I Style first complete their reviewed whole screenplay
foundation. For other styles, freeze a concise whole-film causal spine and ending, then start the first useful
sequence once its exact prompt, references and continuity state are ready. Continue
later planning, reference preparation and assembly while generation runs. Do not
wait for every detailed shot prompt, scene plan or anchor after the applicable
foundation. For daily/unlimited
work, also follow `docs/unlimited-plan-production-preferences.md`, including its
useful 30-second multi-shot default and measured generation-window priorities.

Use one account admission owner and a shared capacity/job ledger across API,
web, projects and collaborators. Assign disjoint sequence IDs to routes. Count
queued, running, submitting and uncertain submissions, including manual web
reservations, against the verified shared limit. Refill with required ready work;
move only unsubmitted sequences between routes. Never submit an extra copy to
test speed, or replay an accepted/uncertain job on another route.

Verify current route access, entitlement, concurrency and price before admission:
a fresh API quote and the web form's actual Free/price state matter. An Unlimited
badge alone does not prove API coverage or concurrency. For zero-credit pass
work require the applicable zero-cost quote; other spending must fit the actual
authorized budget. Do not promise ten concurrent renders, independent route
limits or a speed increase from optimistic cards/progress bars. Measure useful
completed outputs and observed overlap. This is an operating workflow, not a
claim that a new cross-route software scheduler exists.

## Web submissions and reconciliation

Before the single submission, verify the intended sequence prompt, reference
order, completed uploads, exact model, requested resolution/aspect, native audio,
one-generation setting and current price. Preserve the selected model and each
style's identity, source/audio, continuity and actual minimum-shot rules.

Record the click time, sequence, settings, prompt hash and observed identifiers
in the shared ledger. An optimistic UI run/card ID is not an authoritative public
API generation ID. An unconfirmed submission keeps its reservation until its
actual outcome is reconciled; do not replay or free capacity merely because it
does not appear in the API list.

Keep the live generation tab open until its submitted outcomes are tracked. Use
a separate read-only Library tab to refresh server-backed asset results. Do not
reload or close a live generation page to fix a pending card. Browser helpers
must receive the explicit live tab instead of retaining a closed tab in a stale
closure. Reconcile finished files by actual identity/settings/output, then import
and assemble promptly. Preserve exact accepted jobs and unknown submissions on
handoff; record route, tab/receipt pointers and the next safe reconciliation step
without credentials or access-bearing URLs.

Use the existing quick defect checks and final local checks. This workflow adds
no paid scoring, routine review loop, approval gate or relaxation of story,
native speech, budget or two-second actual-shot requirements.
